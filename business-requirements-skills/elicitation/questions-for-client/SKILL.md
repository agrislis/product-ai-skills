# Навык «Вопросы для заказчика» (Questions for the Client)

## Как это работает

1. Пользователь даёт короткое описание задачи (например: «разработать спортивную платформу для города» или «создать мобильное приложение для доставки еды»).
2. Ты формируешь **структурированный список вопросов** для интервью со стейкхолдерами, распределённый по трём группам:

   - **Заказчику** — вопросы про контекст, цели, приоритеты, метрики, ограничения
   - **Администратору процесса** — вопросы про операционку, данные, процессы, интеграции
   - **Конечному пользователю** — вопросы про текущее поведение, желаемые сценарии, боли

3. В конце выдаёшь **таблицу топ-критических вопросов** (3–5 вопросов), которые сильнее всего влияют на постановку задачи, с обоснованием почему.
4. Если пользователь дал недостаточно контекста — задай 1–2 уточняющих вопроса перед генерацией (например, «кто конечный пользователь?», «какой масштаб?»).

## Структура результата

### 1. Подготовка (2–3 строки)
Краткое описание контекста: кто интервьируемые, что стоит изучить заранее, ключевая гипотеза для проверки.

### 2. Вопросы заказчику (видит бизнес сверху)

Разделы:
- **Контекст и цели** — инициатива, решаемая проблема, текущий процесс
- **Приоритеты и объём** — MVP, категории, договорённости с участниками
- **Результат и метрики** — KPI, критерии успеха, финансирование
- **Ограничения** — платформенные требования, сроки, регуляторика
- **Дальше** — кого ещё опросить

Каждый раздел содержит 2–4 вопроса. Ключевые вопросы помечать ⭐.

### 3. Вопросы администратору процесса (владеет операционкой)

Разделы:
- **Текущий процесс и данные** — где хранятся данные, кто отвечает за актуальность
- **Участники и подразделения** — кто наполняет, модерирует, масштаб каталога
- **Процессы и исключения** — сложные случаи, сезонность, обработка изменений
- **Функции и автоматизация** — что автоматизировать в первую очередь, личные кабинеты
- **Интеграции** — внешние системы для интеграции
- **Доступы и следующий шаг** — доступ к данным, кого ещё опросить

Каждый раздел содержит 2–4 вопроса. Ключевые вопросы помечать ⭐.

### 4. Вопросы пользователю (конечный потребитель)

Разделы:
- **Контекст и текущее поведение** — как ищут сейчас, что раздражает
- **Желаемый сценарий** — идеальный поиск, критерии выбора, запись
- **Функции и ожидания** — карта vs список, уведомления, отзывы, оплата
- **Исключения и проблемы** — негативный опыт, различия в сценариях
- **Образцы** — примеры удобных решений из других сфер

Каждый раздел содержит 2–4 вопроса. Ключевые вопросы помечать ⭐.

### 5. Топ-вопросов, влияющих на постановку сильнее всего

Таблица из 3–5 вопросов с колонками:

| # | Вопрос | Почему критично |
|---|---|---|

Каждый вопрос сопровождается кратким обоснованием, почему он критически влияет на архитектуру, объём, стоимость или сроки решения.

## Принципы формирования вопросов

- **Конкретность**: вопросы должны быть практическими, на которые можно получить однозначный ответ, а не абстрактные рассуждения
- **Покрытие рисков**: каждый раздел должен выявлять потенциальные риски (данные устарели, нет процесса обновления, нет интеграций)
- **Приоритизация**: ⭐ помечать вопросы, без ответа на которые нельзя начинать проработку
- **Адаптация под предметную область**: вопросы формулируются в терминах той сферы, которую описал пользователь (не generic-шаблон)
- **Минимум теории**: не включать объяснения зачем задаётся вопрос — только сам вопрос. Краткий контекст допустим в скобках

## Формат вывода

Вопросы выводятся в виде маркированного списка (`- `) внутри разделов с подзаголовками. Для каждого раздела используется группа вопросов, отделённая `---`.

Топ-вопросы — в виде таблицы с 3 колонками.

## Примеры активации

Подходящие запросы:
- «Нужно разработать платформу для аренды самокатов в городе»
- «Создаём мобильное приложение для записи в частные клиники»
- «Какие вопросы задать заказчику по проекту CRM для недвижимости?»
- «Собираю требования к порталу для волонтёрских организаций»
- «Помоги подготовиться к интервью с заказчиком спортивного приложения»

Неподходящие запросы (не активировать навык):
- «Напиши API для создания заказа»
- «Спроектируй базу данных для интернет-магазина»
- «Сделай бизнес-анализ процесса» (для этого есть навык business-analyst)
- «Проанализируй ответы на вопросы из интервью»
