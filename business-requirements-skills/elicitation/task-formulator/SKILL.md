# Навык «Task Formulator» (Формулировка задачи для BA)

## Как это работает

1. Пользователь передаёт **результаты сбора требований**: вопросы, ответы, анализ (можно результат `answer-analyzer` или просто «вот вопросы, вот ответы» в свободной форме).

2. Ты **оцениваешь полноту данных** по шкале:
   - **✓** — полный ответ (вес 1.0)
   - **~** — частичный ответ (вес 0.5)
   - **✗** — нет ответа (вес 0)
   - **n/a** — не применимо к данному респонденту (не учитывается в расчёте)

   Топ-критические вопросы (⭐) имеют двойной вес.

3. В зависимости от уровня полноты:

   | Полнота | Статус | Действие |
   |---|---|---|
   | **≥ 70%** | Зелёный | Выдаёт промпт, допущения минимальны |
   | **30–69%** | Жёлтый | Выдаёт промпт с блоком допущений |
   | **< 30%** | Красный | **Не выдаёт промпт.** Сообщает о критической нехватке данных |

4. Если уровень **зелёный или жёлтый** — формируешь **короткий, ёмкий промпт** (5–10 предложений) на естественном языке, который можно сразу скормить `business-analyst`.

## Структура промпта (зелёный / жёлтый уровень)

Промпт состоит из 4–5 коротких блоков. Без таблиц, без разбивки по ролям, без детальной спецификации — это задача `business-analyst` развернуть промпт в документ.

### 1. Контекст
Кто заказчик, какая инициатива, какая проблема решается, кто стейкхолдеры. 1–2 предложения.

### 2. Границы решения
Что входит в MVP, какие категории / объекты / функции. Ключевые ограничения: сроки, платформа, финансирование. 2–3 предложения.

### 3. Пользователи и сценарии (гипотезы)
Кто будет пользоваться, как предполагается использование. Если данных от пользователей нет — явно указать «гипотеза, требуется валидация». 1–2 предложения.

### 4. Допущения (только для жёлтого уровня)
Список допущений: «следующие пункты не подтверждены, требуется уточнение у заказчика: ...». Кратко, по пунктам, без развёрнутых обоснований.

### 5. Открытые вопросы (опционально)
Вопросы, которые остались за рамками допущений — не влияют на BA сейчас, но нужны для следующих итераций.

## Поведение при красном уровне (< 30%)

Выдать сообщение:

> **Критическая нехватка данных.** Для формулировки задачи нужно ответить минимум на N вопросов из списка.
>
> **Без ответа остались:**
> - вопрос 1
> - вопрос 2
> - ...
>
> **Рекомендация**: дозапросить указанные вопросы у заказчика, после чего повторить попытку.

Показать именно те вопросы, которые остались без ответа (✗) или с частичным ответом (~), сгруппировав по стейкхолдерам. В первую очередь подсвечить топ-критические (⭐).

## Примеры

### Пример входа (зелёный уровень)
> Пользователь: «Вот вопросы и ответы заказчика по спортивной платформе [данные]. Сформулируй задачу для BA.»

### Пример выхода (зелёный уровень)
> **Контекст**: частная компания разрабатывает платформу для поиска спортивных объектов и секций в городе. Инициатива поддержана городским управлением спорта. Проблема — жители не знают о доступных площадках рядом.
>
> **Границы**: MVP — карта с объектами (каталог-справочник). Категории: муниципальные площадки и секции, частично коммерческие. Срок MVP — 3 месяца. Финансирование — собственными силами компании. Госуслуги — на перспективу.
>
> **Пользователи**: жители города, которые хотят найти спортплощадку или записать ребёнка в секцию. Гипотеза: основной критерий выбора — геолокация и расписание (требует валидации с реальными пользователями).
>
> **Данные для наполнения**: единого реестра нет, данные собираются при поддержке управления спорта. Есть база микро-стартапа, которая может стать основой.

### Пример выхода (красный уровень)
> **Критическая нехватка данных.** Для формулировки задачи нужно ответить минимум на 5 вопросов из списка.
>
> **Без ответа остались:**
> - ⭐ Какая проблема решается?
> - ⭐ Что входит в MVP?
> - Есть ли существующие решения?
> - Кто финансирует?
> - Какие сроки?
>
> **Рекомендация**: дозапросить указанные вопросы у заказчика, после чего повторить попытку.

## Принципы

- **Коротко**. Промпт — 5–10 предложений, не больше. Детализацию делает `business-analyst`.
- **Честно**. Если данных нет — не придумывать, а ставить допущение или не включать в промпт.
- **Не блокироваться пробелами** (кроме красного уровня). Жёлтый уровень — это нормально, бизнес-аналитик учтёт допущения в работе.
- **Plain text**. Промпт должен быть готов к копированию и передаче в `business-analyst` без доработок.

## Примеры активации

Подходящие запросы:
- «Вот что мы выяснили у заказчика [данные], сформулируй задачу для BA»
- «Собери промпт для бизнес-аналитика на основе ответов»
- «У нас есть ответы на вопросы, подготовь описание задачи»
- «Результаты интервью: [текст]. Нужен промпт для проработки требований»

Неподходящие запросы (не активировать навык):
- «Составь вопросы для интервью» (для этого есть questions-for-client)
- «Проанализируй ответы» (для этого есть answer-analyzer)
- «Сделай бизнес-анализ по описанию задачи» (для этого есть business-analyst)
