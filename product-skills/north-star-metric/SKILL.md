# North Star Metric

Используй этот навык, когда пользователь хочет определить, уточнить, покритиковать или операционализировать North Star Metric (NSM) для продукта, набора функций или бизнес-линии.

## Что навык обязан выдать

Всегда выдавай эти разделы:

1. **Краткое описание контекста** (Context summary)
2. **Кандидат на engagement game / product motion**
3. **Варианты North Star** (2–4 варианта)
4. **Рекомендуемый North Star**
5. **Входные метрики** (Input metrics) (3–6)
6. **Спецификация определения метрики** (Metric definition spec)
7. **Почему это хороший North Star**
8. **Риски / режимы отказа** (Risks / failure modes)
9. **Требования к инструментации** (Instrumentation requirements)
10. **План внедрения на 30/60/90 дней**

Если пользователь просит только критику существующей метрики — всё равно используй ту же структуру, но сфокусируйся на диагностике текущего North Star.

## Какие входные данные собирать

Если пользователь или репозиторий уже предоставили их — извлеки:

- Название продукта
- Основной пользователь (Primary user)
- Основной клиент / покупатель (Primary customer / buyer)
- Основная Job-to-be-done (JTBD)
- Основной product motion — attention, transaction, productivity или hybrid
- Бизнес-модель — freemium, self-serve, sales-assisted, enterprise, usage-based, seat-based, subscription
- Ключевые действия пользователя
- Желаемые бизнес-результаты
- Существующие KPI / дашборды / схема событий
- Уровень метрики — компания, продуктовая линейка или команда

Если чего-то не хватает — сделай разумное предположение и явно его обозначь.

## Рабочие правила

- Предпочитай **опережающий индикатор** (leading indicator) отстающим результатам вроде выручки, MRR или ARPU.
- Предпочитай метрику, которая отражает **реализованную ценность для клиента**, а не vanity-активность.
- Предпочитай метрику, на которую продукт и маркетинг могут влиять повседневной работой.
- Предпочитай одну метрику, которую **сложно накрутить**.
- Избегай метрик, которые могут расти, пока ценность продукта падает.
- Избегай чисто объёмных метрик, когда требуется порог качества.
- Избегай ситуации, когда NSM можно напрямую «редактировать» одной командой без поддерживающей системы под ним.

## Пошаговый метод

### Шаг 1. Сформулируй продукт и обмен ценностью

Сформулируй одним предложением:
- кто пользователь
- какую работу он пытается сделать
- какую ценность получает

### Шаг 2. Определи product motion

Классифицируй:
- Attention (время / вовлечённость)
- Transaction (сделки / покупки)
- Productivity (работа выполнена)
- Hybrid

### Шаг 3. Сгенерируй 2–4 кандидата North Star

Каждый кандидат должен:
- Быть leading indicator
- Отражать ценность для клиента
- Быть actionable для команды
